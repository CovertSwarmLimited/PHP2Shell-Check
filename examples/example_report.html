CVE-2026-109618 / GHSA-w8hw-w9fx-j79w: RCE via OOM corruption

CVSS 9.2 (CVSS:4.0/AV:N/AC:H/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N) | CWE-416, CWE-755, CWE-824, CWE-1325, CWE-1419

PHP leaves the request with longjmp() on out-of-memory errors. Request memory reachable before it is fully initialised can be left invalid and is then used during request shutdown. Multipart parsing can reach OOM while staying within apparent PHP limits. Exploitation was confirmed against Apache mod_php with default limits. Source analysis suggests PHP-FPM and FrankenPHP are also susceptible.

Mitigations
  • Upgrade to PHP 8.2.35, 8.3.36, 8.4.27 or 8.5.12 or later (the only complete fix).
  • Enforce decoded request size at the front end and lower post_max_size and max_input_nesting_level.
  • Bound multipart parts, headers and uploads, or block multipart at the front end if it is unused.
  • memory_limit=-1 is not a complete mitigation. Avoid RLIMIT_AS and RLIMIT_DATA.

CVE-2026-109619 / GHSA-6wmf-4rv5-p3rp: RCE via stale global state

CVSS 9.2 (CVSS:4.0/AV:N/AC:H/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N) | CWE-416, CWE-755, CWE-824, CWE-1325, CWE-1419

Request-owned state (error, session, object and extension state) can survive in persistent worker globals after the request heap is freed, when a fatal error interrupts an operation before its reset. A later request on the same worker consumes the stale state before initialisation (use-after-free). Named paths include fatal error backtraces (PHP 8.5), session upload progress and INI diagnostics raised before request initialisation.

Mitigations
  • Upgrade to PHP 8.2.35, 8.3.36, 8.4.27 or 8.5.12 or later (the only reliable mitigation).
  • PHP 8.5: set fatal_error_backtraces=0 and restart workers.
  • Set session.upload_progress.enabled=0 and restart workers if the feature is unused.
  • Remove diagnostics from startup and per-request INI configuration. Consider pm.max_requests=1 (FPM).

  • https://www.php.net/ChangeLog-8.php
  • https://www.wiz.io/blog/php2shell-php-rce
